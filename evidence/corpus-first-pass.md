# 사용자 제공 기업보고서 — 첫 파싱 진단

범위: 사용자가 `기업보고서` 폴더의 보고서로 테스트하도록 요청한 뒤 실행한 로컬 진단.
제품용 LLM/Bedrock, AWS, OCR/hybrid 호출 없이 기존 파서와 입력 검사를 그대로 사용했다.
원문은 수정하지 않았으며, 진단 종료 후 50개 파일의 SHA-256이 최초 목록과 모두 같음을 확인했다.
재배포 권리나 외부 모델 전송 승인을 새로 부여한 기록이 아니다.

## 문서 목록

- PDF 50개, 업종 폴더 9개, 총 물리 페이지 7,454개.
- 총 1,118.3 MiB, 문서당 69–265페이지. 파일 해시 중복 없음.
- pypdf 메타데이터 열람은 50개 모두 가능했다. 암호화 표시 2개.
- 메타데이터 열람 중 잘못된 객체 오프셋 경고 2건이 출력됐다. 이 검사는 앱의 엄격한 입력 검사 통과를 의미하지 않는다.
- 기업·보고연도는 파일명만으로 확정하지 않았다. 폴더 분류는 사용자 제공 분류다.

## 실행 조건과 결과

실제 `OpenDataLoaderParser.parse`를 호출했다. OpenDataLoader 2.5.7 + pdfplumber,
Java 21, `hybrid=off`, `synthetic_source=false`다. 저장은 로컬 실험 산출물이다.
기존 기본 제한(100 MiB 입력, 45초 파서 제한, 768 MiB 파서 메모리 예산 등)을 유지했다.
각 문서에서 물리 페이지 3, floor(전체 페이지/2), 전체 페이지-8을 선택했다.
입력 검사는 선택 페이지와 무관하게 원본 PDF 전체를 검사한다.

| 결과 | 파일 수 | 해석 |
|---|---:|---|
| 표본 페이지 파싱 반환 | 4 | 4개 문서의 12개 물리 페이지만 파싱 완료 |
| `PDF_INVALID` | 32 | 사전검사 거부. 모든 파일이 손상됐다는 뜻은 아님 |
| `UPLOAD_LIMIT_EXCEEDED` | 11 | 사전검사 자원·구조 한도에 걸림 |
| `PDF_PASSWORD_REQUIRED` | 2 | 현재 검사는 암호화 표시가 있는 파일을 거부 |
| `PARSER_INPUT_LIMIT` | 1 | APH_2025_SR(KOR)_F.pdf가 현재 100 MiB 입력 상한 초과 |

**4/50은 이 실행 조건에서 표본 파싱까지 도달한 파일 수다. 텍스트·숫자 정확도 8%라는 뜻이 아니다.**
나머지 46개는 표본 텍스트 추출 전 차단됐다. 7,454페이지 전체 파싱/품질 검증은 하지 않았다.

| 파싱 반환 문서 | 선택한 물리 페이지 | 품질 상태 |
|---|---|---|
| 두산밥캣_2025_Sustainability Report_KOR_final.pdf | 3, 58, 108 | fast_preview / 원문 교차검증 미완료 |
| 2025 KB금융그룹 지속가능경영보고서-KSSB 지속가능성 공시기준 적용.pdf | 3, 56, 104 | fast_preview / 원문 교차검증 미완료 |
| 2025_기아_지속가능경영보고서.pdf | 3, 67, 126 | fast_preview / 원문 교차검증 미완료 |
| KOGAS 2025 지속가능경영보고서.pdf | 3, 38, 68 | fast_preview / 원문 교차검증 미완료 |

반환된 4개 문서의 표본 전체에는 `source_unlocated` 88건, `parse_conflict` 19건,
`table_vision_not_run` 27건이 기록됐다. 이는 진단 이슈 건수이며 정답 기반 오류율이 아니다.

## 대표 원인 추적

- 삼성전자: `uploads_security.py`의 금지 키 검사에서 `/AA`가 발견되어 거부됐다.
  검사 시 해당 추가 액션의 형태는 `/D → /Named`였다. 코드나 액션을 실행하지 않았다.
  이 관찰만으로 파일 전체의 안전성을 승인하거나 JavaScript로 단정하지 않는다.
- KT: 방문한 PDF 객체/값 수가 100,001이 되어 현재 100,000 탐색 한도에서 거부됐다.
  당시 압축 해제 누계는 33,576,228바이트였다. 입력 파일 크기 초과와 다른 원인이다.
- 암호화 표시: HD한국조선해양, 삼성물산 보고서. 실제 열람 비밀번호가 반드시 필요하다는 의미와
  PDF의 암호화 표시는 구분해야 한다. 이번에는 암호화 해제·원문 재작성·검사 우회를 하지 않았다.

## 원문 시각 대조 1건

한국가스공사 물리 68페이지를 PDFium으로 렌더링했다. 한 물리 페이지에 인쇄 페이지
134–135가 함께 있는 펼침면이며, 지배구조 데이터 표가 있다. 이 사례는 파서 구조 점검용이고
환경 주장 정답 데이터로 분류한 것이 아니다.

원문과 graph.json을 대조하면 이사회 개최 횟수의 연도별 숫자 17/19/16/14와
CEO 보수의 연도별 값이 올바르게 연결된 표 후보가 있다. 동시에 동일 영역을 부분적으로
겹치는 별도 표가 남으며, 일부 후보에서 헤더가 누락되거나 한 열의 숫자가 여러 줄로 묶인다.
원문 대조는 Codex의 표본 시각 점검이며 독립 인간 정답/전수 정확도 평가가 아니다.
숫자·근거를 검증된 판정 입력으로 승격하지 않았다.

## 재현 파일

모두 현재 작업공간의 `.local/corpus-first-pass/`에 보존했다(외부 업로드 없음).

- `inventory.json`: 실제 경로, 파일 해시, 크기, 페이지 수, 암호화 표시.
- `run_baseline.py`: 기존 파서를 호출한 실행 스크립트.
- `pilot.json`, `baseline.json`, `baseline.log`: 최초 시험과 50개 실행 결과.
- `artifacts/`: 통과 4개 문서의 파싱 manifest/graph/원시 후보/품질 이슈.
- `rejection-diagnostics.json`: 삼성전자·KT의 거부 위치/관련 값.
- `kogas-physical-page-68.png`: 시각 대조에 사용한 원문 렌더링.

실행: `uv run --no-sync python .local/corpus-first-pass/run_baseline.py`.
초기 삼성전자 시험 결과를 재사용하고 나머지 49개를 실행했다. 각 결과는 파일 해시로 연결한다.
`run_baseline.py`를 다시 실행하면 고유 ID의 새 파싱 산출물을 만들고 요약 파일은 갱신한다.
이번 진단에서 애플리케이션 코드·보안 제한·원문 파일을 변경하지 않았다.

## 다음 수정·검증 순서

1. 사전검사 거부를 액션 종류·구조 오류·탐색/압축해제 한도별로 분류한다.
   무해한 탐색 기능과 실행 가능한 액션을 구분하는 계약·회귀 테스트부터 마련한다.
   검사 전체를 꺼서 통과시키지 않는다.
2. 큰 문서의 중복 탐색·자원 사용과 암호화 처리 정책을 검토하고 제한된 실행 경로를 검증한다.
3. 파서 간 표 영역 정렬, 중복 후보, 헤더/행/연도/단위 연결 문제를 고친다.
4. 수정 후 같은 파일 해시·페이지 선택으로 재측정하고, 이후 전체 페이지 범위로 확대한다.
5. 원문 좌표·숫자 묶음 정답을 마련해 정확도를 평가한다. 이 50개를 수정에 사용하면
   이후 독립 holdout 성능 자료로 자동 취급하지 않는다.
