# 개발자 A 재개: 실행 기반과 비용 집계 검증

작업 저장소: `.local/team-publication-20260918`, 브랜치
`feature/developer-a-service-validation`. 기존 연구 저장소와 개발자 B 담당 파일은 수정하지 않았다.
전체 시스템의 서비스 완료를 뜻하지 않는다.

## 실제로 수정한 문제

- 모의 HTTP를 사용하는 추출/태깅 테스트 16건이 달력 날짜 때문에 실패했다.
  테스트 시계만 고정하고 실제 호출 가격 만료 가드는 유지했다.
- 2026-09-18 [Upstage 공식 가격](https://www.upstage.ai/pricing/api)을 다시 확인했다.
  기존 비할인 단가가 동일하므로 과거 가격 스냅샷/영수증은 유지하고 재확인 기록을 추가했다.
  실제 호출 만료 시각은 2026-09-25 00:00 UTC다.
- 예산 확장은 기본 USD10 정책을 덮어쓰지 않고 `probe_extensions`에 명시적 승인을 추가한다.
  기존 사용·예약을 포함한 총 USD20이 상한이며, 재시작·동시 예약·중복 확장·변조된
  정책/비정상 금액을 검사한다. 원래 미정산 6건은 환불하거나 삭제하지 않았다.
- 이미 장부에 있는 동일 요청을 새 영수증 폴더에서 시도할 때 과거 비용이 이번 실행의
  비용으로 집계되던 오류를 수정했다. 이제 `DUPLICATE_PROBE_REQUEST`로 중단하고 이번
  호출 수/비용은 0이다. 가격 만료 등 예약 이전 차단도 과거 비용을 가져오지 않는다.
- 호출 수 제한이 있는 추출 미리보기에서 메뉴성 짧은 문구가 본문보다 앞서 비용을 소비했다.
  문장 종결 기호와 기존 60자 경계를 정렬 우선순위로 사용한다. 짧은 주장도 후보로 보존한다.
  미처리 문장은 unknown이며 전수 처리·정답 판정으로 바꾸지 않는다. 완료된 기존 결과는 불변이다. 선택 순서 변경은 extraction rule descriptor v2로
  구분한다. 과거 완료 결과는 저장된 profile/영수증으로 재생하며, 과거 미완료 작업은
  새 프로필로 조용히 계속 실행하지 않고 profile mismatch로 차단한다.
- 예산/공급자 오류로 조기 종료된 교차 보고서 평가가 시도 횟수를 처리 성공으로 세고
  미시도 문단을 unknown에서 누락하던 집계를 수정했다. attempted/processed/unprocessed를
  구분하고 selected = processed + unknown을 검사한다. 과거 결과 파일은 수정하지 않는다.
- 워커의 지원하지 않는 태깅 모드를 조용히 무시하던 동작을 명시적 구성 오류로 변경했다.
- 평가 CLI의 `--key-file`로 원래 비공개 키 파일을 지정할 수 있다. 키 복사·출력 없이
  팀 체크아웃에서 실행 가능하며 장부는 원래 `.local/upstage`와 동일한 파일을 사용했다.

권한 있는 로컬 개발 시험이며, 독립 gold 평가나 정확도 측정이 아니다.
선택은 기존 개발용 물리 페이지를 재사용했다.

최종 문장 우선 정렬은 오프라인 회귀를 통과했다. 같은 두산 packet 재실행은 중복 방어로
차단됐으므로 최종 정렬의 신규 모델 성능 향상으로 보고하지 않는다.

카카오 서비스 최초 시험에서 보고기간을 2024년으로 입력한 실행은 평가에서 제외한다.
원문 2쪽의 보고기간 2025-01-01~2025-12-31을 확인하여 새 실행
`.local/developer-a-service-kakao-2025`를 만들었다. 이전 불변 실행은 수정하지 않았다.
후보 주장을 최종 환경 입증 주장으로 인정하거나 등급을 부여한 것은 아니다.

실제 실행별 기록은 `developer-a-live-20260918.json`과 비공개 `.local/developer-a-validation`에 있다.
장부 추가 승인 기록/백업은 원래 `.local/upstage/authorization-20260918.json`,

## 실제 PDF 원문 확인 병목

동일한 KB 선택 3쪽에서 bbox가 0.001pt 정밀도로 저장되며 PDF 문자 x0와
0.0005pt 차이만 있어도 잘림으로 처리되는 반례를 재현했다. containment에만 0.001pt
오차를 허용하고 원문 문자열·렌더 이미지 OCR의 정확한 정규화 일치 조건은 유지했다.
0.0005pt 반례는 통과, 0.002pt 잘림은 보류하는 테스트와 기존 숨김/덧칠/레이어 검사를 실행했다.

KB 474블록 중 확인된 원문 블록이 2→135개로 증가했다(후속 실행 62.83초).
나머지는 관계 확인 필요 280, 원문 문자열 불일치 24, OCR 불일치/불가 28, 실제 잘림 7이다.
이 수치는 주장의 정확도/재현율이 아니다. 카카오 373블록, 두산 254블록은 PDF 표시
기능 및 표 관계 검사로 전부 미확정이었으며 해당 가드는 해제하지 않았다.
코드 해시 변경 전 확인 영수증은 보존하고 새 파일에 새 확인 결과를 저장했다.
새 KB 영수증 재생도 실제 OCR 재계산으로 통과했다(62.54초). 원본 그래프의 quality는
변경되지 않았다. 이 재생 지연은 아직 남은 서비스 병목이며, 화면 응답속도 달성을
주장하지 않는다.

## 호환성과 복구

공개 API/운영 DB 스키마 변경은 없다. 로컬 시험 장부에 `probe_extensions` 테이블만
추가되며 기존 정책·사용 행을 변경하지 않는다. 구버전 코드는 추가 한도를 사용하지 않고
기존 USD10 한도/만료 가드로 막힌다. 새 호출 이후 과거 DB 백업을 복원하면 지출 이력을
잃으므로 금지한다. 복구는 호출을 멈추고 현재 장부를 보존한 채 코드만 되돌린다.

추출 선택 우선순위 변경은 신규 제한 미리보기에 적용한다. 이전 완료된 추출/checkpoint는
저장 결과를 재생한다. 진행 중이던 과거 유료 작업은 자동 재시도하지 않았다.

## 후속 검토와 반복 원문 읽기 제거

OpenCode Muse Spark 1.2 Free가 실제 태깅 연결의 8개 계약 병목을 조사했다.
감사에서 제안한 특정 KB 주장 분류의 하드코딩과 미확인 토큰 수 우회는 채택하지 않았다.
독립 extractor/tagger binding과 검증 가능한 선행 분류가 필요하다. 상세 내용은
`live-tagging-contract-audit-20260918.md`의 코디네이터 검토를 따른다.

태깅 1회에서 LocalClaimStore가 검증한 동일 graph를 별도로 두 번 더 읽는 중복을
제거했다. 기존 검증 함수가 snapshot/discovery/graph를 함께 반환하고 워커가 재사용한다.
영속 캐시나 검증 생략은 추가하지 않았다. 회귀 반례는 3회 읽기에서 실패했고,
수정 후 한 번의 실행에서 1회, 새 조회에서는 다시 1회 검증함을 확인했다.
관련 34개 회귀 통과. 실제 처리시간 개선 수치는 아직 별도 측정하지 않았다.

변경된 extraction profile 이후에도 기존 KB v4 실행을 `--invoke` 없이 열어
주장 7개와 HTTP200을 재확인했다. 과거 완료 결과 재생 때문에 모델을 다시 호출하지 않았다.
