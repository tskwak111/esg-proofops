# 50개 PDF 입력 검사 독립 리뷰 — 코디네이터 대조본

OpenCode Muse Spark 1.2 Free가 로컬에서 입력 구조를 조사했다. 제품 코드와
원본 PDF는 수정하지 않았다. 이 조사는 텍스트·표 정확도 평가가 아니다.
워커 초안은 집계 범위와 중간 수정본을 혼동한 부분이 있어, 코디네이터가
원시 결과와 최초 실행 결과를 파일명으로 조인해 아래와 같이 정정했다.

## 최초 차단 원인

| 최초 앱 결과 | 파일 수 | 독립 진단에서 처음 걸린 원인 |
|---|---:|---|
| PDF_INVALID | 31 | `/AA` 키의 일괄 차단 |
| PDF_INVALID | 1 | SK이노베이션: 엄격한 pypdf 읽기 중 endstream/trailer 예외 |
| UPLOAD_LIMIT_EXCEEDED | 10 | 중복 제거 전 pop 횟수 100,001 |
| UPLOAD_LIMIT_EXCEEDED | 1 | 풀무원: decoded 91,382,507 > 75,000,000 bytes |
| PDF_PASSWORD_REQUIRED | 2 | 암호화 표시 |
| PARSER_INPUT_LIMIT | 1 | APH: 108,440,727 bytes > 100 MiB |
| parsed | 4 | 입력 검사 및 각 3개 표본 페이지 파싱 반환 |

진단 스크립트는 APH의 파일 크기 게이트를 적용하지 않고 내부 구조까지 읽었으므로
그 파일도 `/AA`로 집계했다. 따라서 진단의 `PDF_INVALID 33`을 앱의
`PDF_INVALID 32`와 직접 비교하거나 “32개 모두 무해한 탐색”이라고 할 수 없다.
첫 거부 사유는 이후에 검사되지 않은 다른 문제의 부재를 증명하지 않는다.
`/Named /Print` 관찰도 있어 모든 Named 액션을 탐색으로 허용하지 않는다.

## 구현 리뷰에서 확인한 점

- `/AA` 자체의 차단을 해제하더라도 내용·체인·숨은 객체 검사는 유지해야 한다.
- 중간 수정본이 일반 `/URI` 링크까지 거부하는 회귀를 발견했다. 기존 테스트는
  링크를 저장하되 외부 접속하지 않는 동작을 이미 요구한다. 새로운 승인 사항이
  아니라 기존 계약을 보존할 수정 사항이다. 최종 통합 결과는
  `corpus-repair-verification.md`에서 별도로 기록한다.
- `/A`는 태그 구조의 속성에도 사용되므로 모든 `/A`를 액션으로 간주하면 안 된다.
- 고유 노드 기준으로도 KT의 128,832개 객체는 기본 100,000개 제한을 초과한다.
  중복 계산 수정과 자원 상한 상향은 서로 다른 변경이다.
- 암호화 2개는 워커가 빈 비밀번호로 메모리 내 열람 가능함을 관찰했지만,
  앱은 현행 계약대로 거부한다. 원본 재작성이나 앱의 자동 복호화는 도입하지 않는다.

상한 상향·암호화 특례·손상 복구·새 품질 이슈 유형은 이번 수정에 추가하지 않는다.

## 근거 파일

최초 실행: `.local/corpus-first-pass/baseline.json`, `inventory.json`.
워커 진단 원본: `.local/corpus-repair/input-diagnostics.json` (50행).
초안 보존: `.local/corpus-repair/input-review-raw.md`.
진단에는 읽기 전용 보조 스크립트도 포함되므로 모든 진단이 앱의 격리 경로를
통과했다고 주장하지 않는다. 최종 앱 재시험은 기존 bounded parser 경로로 수행한다.
