구현
1. 원본 PDF를 로컬 API에 전달하고 물리적 쪽 번호로 분석한다.
   PDF 해시가 일치하는 NAVER 전체 A100 Docling 결과는 고정된 manifest 해시와
   모든 산출물 해시를 확인해 재사용한다. 다른 PDF는 A100 Docling으로 파싱한다.
   traverse_pictures=True가 적용된 파서 결과를 사용한다.
   제어문자 제거는 표시/비교 계층에만 적용하고 원본 텍스트·해시를 보존한다.
2. 독립 교차검증: Docling 인용을 PDF의 같은 좌표 영역과 대조하고 Upstage
   standard/enhanced 원문·영역과 비교한다. 인용 합의와 표 구조 검증은 다르다.
   기존 parse_conflict/table_grid_overlap은 짧은 값 일치로 해제하지 않는다.
   NAVER의 기존 217쪽 standard/180쪽 enhanced 영수증을 재사용했다.
   새로운 보고서에 독립 파서 영수증이 없으면 검토 필요로 남긴다.
   Upstage 예산을 초기화하거나 기존 한도를 우회하지 않았다.
3. 정규화: 사업장·연도·수치·단위·지표·분모·각주를 인용/쪽/좌표와 연결한다.
   쉼표, 한국어 수량(3만), 근사값(약 25%), 반기(2025년 하반기)를 처리하고
   원문 표현을 따로 보존한다. 다른 수치 문장의 분모 연결은 binding_conflict로 보류한다.
4. 요소 후보를 기존 G/P/M 매핑에 연결하되 의미 연결 승인과 원문 인용 검증은 구별한다.
   한 번의 모델 출력을 ConfirmedTags나 3회 합의로 위장하지 않는다.
   api/rulepack.json은 draft·미승인이다. 실제 등급 엔진 호출 전 승인 게이트에서
   보류한다. 실제 보고서를 synthetic으로 표시해서 엔진을 우회하지 않았다.
   따라서 현재 확정 등급은 0이며 이 단계는 최종 판정 완료가 아니다.
5. 차트는 별도 OpenAI 비전 경로에서 파싱하고, 목표/실적/달성률 연결도 구조화한다.
   PDF에 없는 숫자는 거부한다. 숫자 존재와 범례 문구 일치를 별도로 검사한다.
   읽은 수치·범례 연결은 검토 후보이고 보증/확정 등급으로 승격하지 않는다.
   모든 OpenAI 호출은 기존 4달러 공유 예산 장부를 사용한다.
6. DART OFF가 기본이다. ON 시 기업코드·사업연도·접수번호·연결/별도를 입력한다.
   실제 공시 후보 조회 버튼, 후보 선택, 접수번호/연도 일치 검사, 재무제표 조회를 연결했다.
   C1은 승인된 기업/사업장 범위 매핑 필요, C2는 연도 관찰값만 비교한다.
   정확한 기간을 주장 연도로 만들어내지 않는다. C3/C4는 금액 투자/매출 비중
   트리거를 구분한다. 필요한 근거가 없는 경우 입력 필요/검토 필요로 유지한다.
   기존 C1~C4 순수 대사 엔진은 승인된 정책·패킷이 없어 실제 확정 판정까지 호출하지 않는다.
   단순 조회 성공이나 미래 목표 연도 차이를 일치/불일치 확정으로 표시하지 않는다.
7. 결과 화면은 분석 사례의 요약 카드, 상태 탭, 검색/트랙/등급 필터,
   문장 목록과 동일 ClaimDetail 구성요소를 사용한다. 근거 후보, 정규화, DART 상세를 추가했다.
