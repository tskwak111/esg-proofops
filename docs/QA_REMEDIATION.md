## 현재 실행

- OpenAI 직접 호출은 사용자 요청에 따라 `gpt-6-sol`입니다. 누적 승인 상한은 USD 10이며 기존 장부의 정책·비용·미처리 예약을 보존합니다. 미처리 예약은 증빙 없이 해제하지 않습니다.

- Upstage 기본 권한은 USD 10이며, 과거 USD 20·22·30은 개별 장부에 기록된 추가 권한 또는 상한입니다. 실제 사용 가능 금액의 기준은 해당 **기존 장부**의 `authorized_limit_usd - committed_usd`입니다. 문서의 숫자로 권한을 추가하거나 새 장부를 만들어 우회하지 않습니다.

## 동작과 표시

인증 API만 시작하려면 `./scripts/Start-ParserLab.ps1 -Service Backend`를 별도 터미널에서 실행합니다. 이는 8000 포트의 API를 시작할 뿐 계정·권리·동의·실행 바인딩을 자동 생성하지 않습니다. 인증 API 연결 실패를 정적 데모로 바꿔 보여주던 동작도 제거했습니다.

- GPU 작업 전에 OpenAI 가용 예산을 검사하고 각 유료 요청 전에 원자적으로 예약합니다. 사전 검사는 견적이며 이후 다른 요청이 비용을 쓸 수 있습니다.
- 로컬 PDF는 한 번 전송하고 이후 10쪽 묶음은 문서 ID만 전송합니다. 서버는 현재 세션 문서 한 개(최대 100MB)를 메모리에 보관합니다. 다음 업로드나 서버 재시작 시 교체됩니다. 분석 원문·차트는 설정한 제공자에게 전달됩니다.
- 북마크/목차는 실제 페이지 내용과 대조합니다. 환경 본문을 부록보다 우선 선택하고 60쪽 제한·제외 쪽 수를 표시합니다. 자동 선택은 후보이므로 페이지 목록을 확인해야 합니다.
- 로컬 태깅은 서로 다른 요청 3회를 저장하고 동일 인용·연결의 다수결로 후보를 합칩니다. 모델 합의는 의미 승인이나 전문가 검토를 대체하지 않습니다.
- 저장소 기본 규칙팩은 draft로 보존합니다. 복사본의 웹 분석에는 사용자가 위임한 프로젝트 규칙 검토를 별도로 설치했습니다. `scripts/install_lab_analysis_policy.py`가 승인 DB와 해시 고정 registry를 만들며, 런타임은 이를 읽기만 합니다. 전문가 정답·법적 적합성·개별 주장 승인이 아닙니다. 새 주장에 과거 데모 정답을 가져오지 않습니다.
- DART 기업코드와 연도는 빈 값에서 시작합니다. C3/C4 입력 초안에 실제 인용·공시 출처·후보 계정과 누락 입력을 남깁니다. 범위·기간·분류 정의·정책 승인이 없으면 최종 대사를 보류합니다.
- `/live`는 로컬 접근 토큰을 받아 OpenAI Luna와 같은 예산 장부를 사용합니다. 공개 페이지와 404는 인증 세션을 조회하지 않습니다.

## Vercel 설정

두 함수는 `X-Forwarded-For`를 신뢰하지 않습니다. Vercel의 전달 헤더를 사용하고, 로컬 HTTP에서는 실제 연결 주소를 사용합니다.

Vercel 유료 호출에는 `LIVE_REDIS_REST_URL`, `LIVE_REDIS_REST_TOKEN`으로 연결한 공유 Redis REST 저장소가 필요합니다. 미설정·접속 실패는 유료 호출 전에 차단합니다. 분당 요청 수와 일일 최대 비용 예약은 Lua로 원자적으로 처리합니다. `LIVE_DAILY_TOTAL_USD` 기본값은 0.50이며, 모든 요청에 최대 USD 0.123을 보수적으로 예약합니다. 실패 예약도 유지하므로 실제 청구액보다 먼저 막힐 수 있습니다. OpenRouter 자체 키 한도는 별도로 유지해야 합니다.

파싱 15초, 모델 호출당 12초(보고서)·15초(문장), 한도 조회 5초 및 공유 예약 3초로 제한합니다. 문장 분석의 유료 자동 재시도는 제거했습니다. 공급자 지연이나 로컬 PDF 처리 시간 때문에 완료가 보장되는 것은 아닙니다.

## 근거 연결 및 판정 엔진 연동

- `evaluation/report_decisions.py`에서 원문 좌표·인용·파서 충돌·3회 태깅을 확인한 요소를 기존 순수 Python 규칙 엔진에 전달합니다. 실데이터에서 synthetic 우회를 사용하지 않습니다.
- 같은 문서 전체의 파싱 블록에서 근거를 검색합니다. 수치·목표연도는 직접 주장/검증된 표의 해당 열에 한정합니다. 다른 위치의 방법론·경계는 기업·지표·기간·범위 연결이 필요하며 보증 범위는 별도 검토합니다.
- `unknown`, `absent`, `conflict`, `present`를 구분합니다. 검색 누락을 부재로 바꾸지 않습니다. 확정할 수 없으면 가능한 등급 범위와 미해결 요소를 보존합니다.
- 절감 활동을 수치 산정 방법론으로 오인하거나, 기준 없는 낮음/높음을 정량 근거로 자동 확정하지 않습니다. 해당 후보는 원문을 보고 검토해야 합니다.
- 추출을 창 단위로 나누고 32개 상한에 닿으면 분할합니다. 미처리·상한·좌표 누락·과대 블록은 coverage에 기록합니다. 새 문서의 전체 근거 파싱은 최대 400쪽이며 이 범위를 넘으면 전체 검색 완료를 주장하지 않습니다.
- 웹의 ‘근거 연결 검토 · 재계산’은 검토자와 이유를 받아 새 불변 리비전을 저장합니다. 보증 확인·전수 검색 후 부재 확인은 별도 명시가 필요합니다. 임의 등급 입력, 파서 충돌 덮어쓰기, 오래된 리비전 분기는 거부합니다.
- JSON/CSV/HTML에 확정 등급과 등급 범위를 구분합니다. 화면 요약도 규칙 등급 계산과 범위 계산을 나눕니다.
