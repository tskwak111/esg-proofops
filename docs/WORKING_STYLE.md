# 개발 방식 교정 기록 — 2026-09-19

사용자는 ESG 작업뿐 아니라 다른 작업에서도 과도한 구현·검증과 느린 진척을 지적했다. 앞으로 요청 범위를 줄이지 않고, 실제 결과 개선 대비 비용과 시간을 기준으로 우선순위를 정한다.

관측된 문제: 일부 보고서의 개별 실패에 반복 집중, 작은 변경마다 넓은 회귀 검사, 외부 OCR의 대표 입력 효용 확인보다 주변 기반을 먼저 확장, 전체 성능 프로파일링 지연, 중복된 상태·검증 기록. 외부 OCR의 최근 추가 복구는 문단 1개·검토 후보 2개였으므로 구현량을 성능 향상으로 설명하면 안 된다.

개선 기준: 큰 병목부터 측정 → 대표 입력에서 접근법의 효과 확인 → 공통 원인 수정 → 영향 범위 검증 → 통합 시 필수 전체 검사. 단순 작업에는 이 절차를 별도 문서·단계로 만들지 않는다. 개선이 정체되면 같은 사례를 계속 보정하지 말고 다른 접근을 비교한다. 검증된 비교 입력과 미사용 사례로 일반화 여부를 구분한다.

유지할 것: 비용 중복·권한·테넌트 분리·원문 인용·불변 revision 보호, 실패 및 unknown의 정직한 표시. 하지 않을 것: 정확도 수치 창작, 실패 테스트 삭제, 사용자 범위 축소, 중단 지시 무시.

지속 적용: 개인 `outcome-first` 스킬과 전역 `~/.codex/AGENTS.md`, 원본/팀 체크아웃의 AGENTS.md에 반영했다. 기존 스킬 전체를 고치거나 비활성화하지 않았다. 이번에는 지침·스킬 파일만 변경하고 형식/연결/변경 범위를 확인한다. 새 세션의 실제 준수 효과는 아직 측정하지 않았으며 장기 재발 방지를 보장한다고 주장하지 않는다.
