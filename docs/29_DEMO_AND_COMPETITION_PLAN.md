# 29 · 공모전 데모·제출 구성

> ESG ProofOps · 개발 명세 1.0 · 2026-09-08
> 도메인 정본: `sources/PROJECT_DOMAIN_V2_ORIGINAL.md` (원문 2.0, 2026-09-07).

## 1. 데모가 보여 줄 핵심
기업의 실제 환경성과를 AI 가 판결하는 시연이 아니라, 공시의 한 문장을 골라 근거가 어디에 있고 무엇이 빠졌는지 보여 주는 시연이다. 도메인 내용은 원문을 유지하고 발표는 기술 파이프라인과 추적 가능한 산출물에 집중한다.

시연 순서: 공개/사용권한이 확인된 보고서 입력 → 물리페이지/표 구조 확인 → 성과+목표 claim 분리 → 요소와 근거 하이라이트 → 보증의견서의 대상/기간/경계 연결 → 불일치 한 건을 검토자가 태깅 수정 → 자동 재채점 → 이전/이후 revision 과 감사 리포트 export.

## 2. 시연 사례 세트
A. 목표연도+감축률만 있는 원문형 예시는 E1/INCOMPLETE, 기준연도/범위/진척/계획 결손을 보여준다.
B. 본문과 표의 값이 다른 사례는 ‘거짓’이라고 단정하지 않고 수치검산 conflict 와 원문을 보여준다.
C. 기관명은 있지만 다른 사업장/기간만 보증한 사례는 covered 가 아닌 상태를 보여준다.
D. 세이프하버 범주는 가정·방법·한계의 기록을 보여 주고, 승인되지 않은 E 매핑/법적면책은 판정하지 않았음을 표시한다.
E. 표 파싱 실패는 E0가 아니라 unreadable/review 로 분기하는 것을 보여준다.

## 3. 발표 자료에 담을 증거
원문→source→claim→element→rule→decision→review→export 의 한 사례 trace, 실제 run manifest, 파서·태깅·보증·등급의 각각 metric/분모, 기존 baseline 과의 차이, document 당 token/비용/시간, 실패/검토율을 담는다. 비공개 원고·실명 개인정보는 사용하지 않는다. 기존 silver 의 replay 정확도나 OD 공개벤치마크를우리서비스의한국어실증정확도로전용하지않는다.

## 4. 시연 장애 대응
실시간처리실패시동일 version 의저장된 run artifact 를 replay 할수있다. 이때 live 가아닌저장된실행재생임을화면과발표에서밝힌다. 합성 fixture 는합성이라고표시한다. 최신 profile 로다시실행한것처럼오래된 cache 를보여주지않는다. 네트워크없는 fallback 도 sourcehash/rulehash/실행시점은유지한다.

## 5. 제출 패키지 체크
문제정의/도메인일곱산출물, AWS 서비스배치, 데이터권리/보안, 실제 metric·baseline, 원문 근거시연, 한계/검토경로, 팀역할/개발기여, reproducibility manifest 를포함한다. 대회사용가능서비스·제출파일형식·2026마감은공식공지와팀계정으로확인해야한다. 공개페이지의연도없는날짜를이번문서에서확정일정으로복제하지않았다.[S13]
