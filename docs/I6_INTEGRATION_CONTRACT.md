# I6 integration contract

New runs use `finals-20261012-v6`, combining the immutable I5 policy with K5
literal sentence/cell/header context and K6 coverage, citation, risk and facility
candidates. All earlier policies, source readers, revisions and reports remain
hash-selectable. New extraction and analysis hashes separate the changed behavior.

K5 context is interpretation only: it cannot grant numbers, years or element
credit. K6 restores literal observed rows and explicit target spans, pairs repeated
units only with selected quantities, vetoes risk-only goal votes, and passes
individually verified facility headers as boundary candidates. LLMs extract/tag;
pure Python grades. Unknown/conflict/unreadable remain distinct from absence;
present requires verified, attributable evidence. Assurance matching stays intact.

I4 response identity and S1 whole-receipt guards, H1 selected-page parsing, I5
source-local table failures, v12 verification and S2 budget/scheduling remain.
The v6 parse scope checks the unchanged S1 implementation hash before reuse.

The K5 optional read field `sentence_context` is documented in API contracts.
There is no database migration, write API change or dependency change. If-Match
and immutable prior revisions remain. Rollback selects the I5 hash for new runs
and keeps v6 readers/artifacts; old runs never acquire new context or credits.

Evaluation uses disposable streams and frozen source/gold inputs. Free replay
cannot validate new model behavior; the five specified fresh canaries do that.
The Linux LG 13-page path uses 2 CPU/4 GiB, cgroup memory measurements and a cold
publication process. The shared I6 spend cap is USD 0.80, including OCR/parse.
Local commits only; pushing, deployment and EC2/runtime.env are coordinator actions.
