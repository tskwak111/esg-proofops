## 1. 제품 정의
기업 공시 문장에 근거가 있는지, 어디에 무엇을 보완해야 하는지 보여 주는 발간 전 검토 도구다. 주요 고객은 인증기관·회계법인 검토자, 공급망 담당자, 공시 작성자다. 이 패키지는 실제 환경성과 판정·법률 자문·공식 인증 업무를 추가하지 않는다.

## 2. 사용자와 완료되는 일
| 사용자 | 시작 상황 | 시스템에서 하는 일 | 성공의 증거 |
|---|---|---|---|
| 작성자(editor) | 공개 전 원고가 준비됨 | 기업·기간·산업·문서 입력, 실행, 결손 확인 | 수정할 요소와 원문 위치를 곧바로 찾음 |
| 검토자(reviewer) | 자동 태깅이 충돌함 | PDF 와 후보 근거 비교, 태깅 확정 | 무엇을 보고 확정했는지 이력으로 남음 |
| 관리자(admin) | 팀·규칙·보안 설정 필요 | 구성원·규칙팩·보존·동의 정책 운영 | 테넌트 밖 접근 없이 버전별 재현 가능 |
| 조회자(viewer) | 결과만 검토함 | 요약·근거·export 조회 | 읽기 권한만 있고 판정 상태를 바꾸지 못함 |

주요 여정: 로그인 → 문서 등록 → 검증된 버전 선택 → 기업/기간/산업 확인 → 적용 규칙·처리범위·예산 확인 → 실행 → 처리 품질과 분모 확인 → 주장 상세에서 원문·결손 확인 → 사람 검토 → 스냅샷 export. 원고 수정은 기존 PDF 덮어쓰기가 아니라 새 버전으로 입력한다.

## 3. 우선순위와 비목표
P0는 공시 검토의 수직 경로 전체이며 P1은 다년도 비교와 광고 별도 모드다. P2는 고객별 검토 템플릿·대량 협력사 관리·검토자 생산성 기능으로, 현재 API 에 미리 넣지 않는다. Future 는 원문 §3.7의 PCAF/해외 규정 확장이고 승인된 별도 요구사항이 있어야 개발한다. 자동 공시 원고 발행, 기업 순위, 종합 투자점수, 외부 뉴스의 진실 검증, 자동 법률 면책 확정, 결제·청구 시스템은 현재 범위 밖이다.

## 5. 성공 측정과 제품 제약
측정 목표와 실측을 구분한다. P0에서 문서당 수정 가능한 결손 비율, claim 원문 클릭 성공률, 요소별 정밀도/재현율, 보증 coverage 오류, 검토자 수정률·처리시간, 문서당 토큰·비용을 측정한다. 하나의 종합 정확도로 모든 단계를 대표하지 않는다. 골드가 없는 데이터에는 정확도를 기재하지 않는다.

초기 엔지니어링 제한은 PDF 100 MiB/300 페이지, 동시 실행 tenant 당 2건, 실행당 누적 LLM 입력 토큰 2,000,000/출력 300,000이다. 이는 성능·원가 보장이 아니라 가드레일 시작값이다. 범위를 넘기면 분할 등록 또는 관리자의 검증된 설정 변경을 요구하며 자동 샘플링하지 않는다. 문서에 포함된 표는 원문 요구에 따라 비전 비교를 거친다. PDF 가 아닌 사업보고서 원본 형식은 P0에서 공식 원본의 PDF 출력본을 입력받고 출처를 기록한다. HTML/HWP 원본 직접 파서는 별도 adapter 승인 전 지원한다고 표시하지 않는다.


## 등록 보조 기능
FR-033(P0)은 기업 레지스트리와 실행 옵션 조회다. 사용자가 문서 등록 화면에서 기존 기업을 선택하거나 기업명을 입력해 새 company_id 를 만들 수 있어야 한다. tenant 의 승인된 옵션만 선택하게 하며 UI 에 숫자 ID 를 직접 입력하도록 요구하지 않는다.
