# PB3 Linux source gate

PB3 evaluated the deployment Dockerfile on Linux arm64 with networking disabled.
The gate failed; v7/v8 are not added to `hosted_rendered_readers.json`.
The v6 defaults, historical reader bytes, stored receipts, tags and grades remain intact.

Mac v7/v8 policies pin an unavailable CPU raster runtime. The actual Linux image
pins its available Tesseract executable and language data. These policies are
different; the existing receipt guard must reject direct historical replay.
Fresh Linux receipts are separate evaluation artifacts, never replacements for Mac receipts.
All 50 saved OCR pages render to identical decoded RGB pixels on both platforms,
but their PNG byte hashes differ. The exact PNG-bound OCR cache correctly refuses
these different encoded inputs; the evaluator does not bypass that trust boundary.

The evaluator reproduces saved extraction responses on Mac and compares native
cell proofs in Linux. Its fixed-claims mode uses the exact Mac parse graph hash
as a diagnostic input, then performs fresh Linux claim attestation and receipt
recomputation. This does not approve a historical Mac parse receipt on Linux.
Its private pickle fixture is generated by the evaluator and hash-pinned; it is
not a product upload format. Provider calls are forbidden throughout evaluation.

Original NAVER p88 exposes two v8 admitted spans combining PUE with a heading
in another native row/column. The located-cell path validates individual cell
literals but does not impose the native order guard used for recovered cells.
Preserving parser row/column IDs alone does not prove native row/column ownership.
The zero-false-verification gate therefore fails even where cell proofs reproduce exactly.

Details, crop findings, platform differences, commands and check results are in
`outputs/agent-results/R108-redesign/lab/perf/PB3/`. No API/DB migration, dependency,
push, deployment, cloud action, model call or new grade is part of this evaluation.
